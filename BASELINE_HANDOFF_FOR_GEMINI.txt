NON-NEGOTIABLE DATA AND SCIENCE RULES
-------------------------------------
- Original camera photograph is NEVER input to the detector during evaluation.
- Do not test on training data, reuse public viewer previews as final test,
  select thresholds on test labels, or infer correctness from a 16-image run.
- Keep all derivatives of one original scene in the same split when IDs are
  available. Audit source overlap separately from generator overlap.
- Do not assume a dataset's published splits are source-disjoint; verify.
- Do not call a heatmap a ground-truth mask or a raw score an AI probability.
- Keep requested edit masks, reviewed semantic-edit masks and pixel-difference
  masks distinct. VAE processing/compression can change outside the edit region.
- Preserve source/image permissions and record exact dataset and model licenses.
- Do not overwrite existing data or silently accept licenses/terms on the user's
  behalf. Continue with permissible alternatives if a source is blocked.
- Do not download and run untrusted checkpoints as unrestricted pickles; favor
  safetensors where supported. Use trusted official checkpoints and safe loading
  supported by the framework; do not bypass security checks to force loading.
- Never present a score calculated from an invalid mask/polarity/threshold as
  a benchmark result. Report what is unknown and the exact step that failed.
- No paper claim of SOTA, superiority or statistical significance without a
  fair comparable protocol and supporting results. A baseline may fail.

STEP 5 — VALIDATION, THRESHOLDS AND TEST
-----------------------------------------
1. Decide score direction and map polarity using documented model semantics or
   documented validation analysis. If source conflicts cannot be resolved,
   report raw values with ambiguity, and leave affected metrics NOT COMPUTED.
   Never pick whichever direction looks better using held-out test labels.
2. On validation data ONLY, define image score threshold and mask threshold.
   Record selection rule, seed and thresholds in a locked JSON config. For
   comparison to a published method, separately reproduce its stated fixed
   threshold/protocol. Avoid per-image oracle thresholds or best test thresholds.
3. After fixing all settings, run the held-out test without providing labels or
   masks to the detector. No hyperparameter changes after examining test results.
4. Image-level metrics: count TP, FP, TN, FN; accuracy, balanced accuracy,
   precision, recall, F1, false positive rate and ROC-AUC, with score direction
   stated. ROC-AUC requires both classes and meaningful continuous ordering.
   Also report PR-AUC with class prevalence for imbalanced data, when applicable.
5. Localization: per-image pixel IoU and pixel F1 for edited test images using
   verified masks, fixed threshold and explicit nearest-neighbor preprocessing.
   Report exact aggregation, zero-union policy, valid pixels and evaluated N.
   Separate area bins <2%, 2–10%, >10%; include sample counts and report NA
   when no samples. Include negative-image mask area/false positives separately.
6. Confidence intervals: bootstrap at ORIGINAL-SOURCE level when source IDs are
   available; document number of resamples and seed. If IDs are unavailable,
   disclose the limitation; don't imply image-wise bootstrap removes dependence.
7. Run the SAME manifest and locked metrics for all compared models; record
   whether pretrained models saw related data, model input resolution, and
   whether target-dataset fine-tuning occurred. Do not directly compare numbers
