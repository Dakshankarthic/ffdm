GEMINI HANDOFF: 10,000-IMAGE TRAINING AND REINFORCEMENT LEARNING
14 November 2026 | Project: I:\icvgip workshop

PURPOSE
Build and evaluate a single-image AI inpainting detector and localization model
for a research paper. The inspected image alone is used at inference. Masks and
original images may be used for supervised training and evaluation when available.
The user proposes training on 10,000 images, analyzing errors, then investigating
reinforcement learning (RL). Complete the supervised work first and run the RL
pilot only after its prerequisites are met. Never invent results or claim SOTA.

EXISTING MATERIAL
Read FDDM_SUPERFRAME_PAPER_PROGRAM.txt, FDDM_Research_Flow_and_Log.txt, and
controlled_localization/src/controlled_localization/train_frame.py before changes.
Existing v2 checkpoint: controlled_localization/runs/super_frame_v2_run/best.pt.
The previously inspected 100-image set is DEVELOPMENT ONLY, not a fresh final test.
Its SDXL subset had 10/20 correct; a scoring experiment achieved 11/20, with all
six edited-image misses remaining. These are small exploratory results.

MUST FIX FIRST
Current train_frame.py takes a 384x384 crop but preserves the whole-image label.
A crop from an edited image can contain no annotated edited pixels and still get
a positive classification target. A read-only simulation with seed 42 and 20 crops
per positive training image found 4,285/16,200 empty-mask crops; this estimates
sampling incidence, not the historical training batches. Center-crop validation
also misses some edits. Treat crop-level labels as local edit-presence labels,
keep whole-image labels separate, and validate mask provenance. A mask-empty crop
is background for local supervision, not necessarily a globally pristine image.
Missing or invalid masks must fail validation rather than silently become zeros.

PHASE 2: SCALE TO 10,000 IMAGES
[ ] Acquire eligible high-resolution genuine and edited images with masks from
    documented sources; respect licenses. Match genuine and edited source and
    processing as far as available. Report any imbalance or collection shortcut.
    Preserve quality, but also retain realistic JPEG and resize variants without

[ ] Run a small smoke test before a pilot. Train with mixed precision if supported,
    gradient accumulation or smaller batches as required for the 8 GB GPU; log
    peak VRAM, runtime, updates and resumed checkpoint state. Use Kaggle only if
    accessible and document environment and data transfer. Never assume access.
[ ] Run full 10,000-image training only when data eligibility checks pass. If the
    target is unavailable, run the largest defensible pilot and report the gap.
    Use validation for checkpoint and threshold selection, not the final test.
    Record per-epoch loss and sample counts; do not promise accuracy gains.
[ ] Save image-level scores, labels, IDs, predictions, masks and heatmaps with
    metrics. Report accuracy, F1, AUROC, sensitivity, specificity and false
    positive rate; edited-image IoU and pixel F1; clearly define aggregation and
    thresholds. Report counts and confidence intervals where feasible.

PHASE 3: DIAGNOSE AND IMPROVE
[ ] Inspect false positives and false negatives from training/validation only.
    Break down by generator, edit size, source, resolution, compression and edit
    type. Save examples and an error report; note small subgroup sample sizes.
[ ] Mine hard examples from training data only. Add difficult genuine textures,
    mask-containing tiny edits and background patches. Keep ordinary samples too.
    Compare against the corrected baseline at matched training and compute budget.
[ ] Consider supervised original/edit pair ranking only if verified matched pairs
    are available. Run a same-data no-ranking ablation. Original not required at
    inference. Keep data availability and pair provenance explicit.

PHASE 4: RL PILOT, AFTER SUPERVISED BASELINE
[ ] First identify a sequential decision: choose the next image tile to inspect,

    observations, termination and the compute budget. No ground-truth masks or
    labels may enter the policy observation at inference.
[ ] Train an RL policy on TRAINING sources only; use labels/masks only to compute
    training rewards for correct detection/localization, false alarms and cost.
    Freeze reward, policy choice and threshold using validation only. Specify

[ ] Compare with the SAME frozen detector and SAME tile/compute budget using grid,

[ ] If prerequisites or resources are unavailable, document the blocker and
