==========================================================================
1. DECISION AND SCOPE
==========================================================================
Build and evaluate a single-image detector that localizes small AI content
edits while avoiding false alarms caused by ordinary whole-image processing.
The paper must test a scientific hypothesis, with reproducible evidence.
It is not a website project. EchoSeam is historical work, not a requirement
for this new architecture. Preserve its files and results for traceability.

Research question:
Can matched training examples and localization consistency improve small-edit
localization on unseen editors while controlling false alarms on photographs
that have only undergone non-content processing?

Input at deployment: ONE suspect RGB image, with no original or edit mask.
Outputs: edit score, edited-region probability map, binary mask at a frozen
validation threshold, overlay, and processing/runtime metadata.
The score is model evidence, not proof of authenticity or a calibrated
probability unless calibration has been fitted and evaluated separately.
The detector cannot reconstruct what a removed object originally looked like.

Originals, masks and processing recipes are allowed during training and
evaluation. They must NEVER become required inputs to deployment inference.
Primary scope: local insertion, replacement and removal using AI editors.
Whole-image generation and ordinary manual edits are separate evaluation
categories, not automatically covered by this local-edit claim.

The new approach has no final marketing name. Working identifier:
controlled_localization_v1. Naming is not a research contribution.

2. WHAT IS KNOWN, WHAT IS PROPOSED, WHAT IS MEASURED
==========================================================================
KNOWN FROM PRIOR WORK:
- RGB and forensic feature fusion is established (TruFor, FUSED).
- Background artifacts can drive AI detection decisions (INP-X).
- Reconstruction-based refinement already exists (IFA-Net).
- Semantic object boundaries can mislead localization (GAP-SAM).

PROPOSED HERE, NOT YET PROVEN:
- Matched examples with and without local edits and processing variations.
- Consistency supervision to preserve localization across those variations.
- Explicit negative controls for images without deliberate content edits.
- Native-resolution tiles for small regions and controlled false-alarm tests.

None of those components alone is claimed to be new. The contribution must
be established against related methods, then supported by ablations and
independent evaluation. Do not call this SOTA, novel, robust or accurate yet.

3. TESTABLE MODEL: EXACT FIRST VERSION
==========================================================================
Purpose: isolate whether the proposed TRAINING mechanism helps before
spending compute on larger backbones or adding more modules.

Test model T0 architecture:
1. Image input and coverage
   - Decode RGB consistently, apply EXIF orientation once, retain dimensions.
   - Use 384x384 native-resolution tiles, stride 256, including right/bottom
     edge tiles. Pad smaller images and retain a valid-pixel mask.
   - Do not resize an entire large image to 256px and call it native detail.
   - Training uses sampled tiles; evaluation covers the entire image.

2. RGB branch
   - ImageNet-pretrained ResNet-18, using its four feature stages at strides
     4, 8, 16 and 32; channels 64, 128, 256 and 512.
   - Apply the pretrained RGB normalization only to this branch.
   - Initially freeze BatchNorm running statistics for small-batch training.
   - Fine-tune convolutional weights; record exact pretrained weight ID/hash.

3. Forensic branch
   - Operate on RGB values scaled to [0,1], before RGB standardization.
   - Fixed high-pass initialization: horizontal difference, vertical
     difference and Laplacian applied per color channel (9 residual maps).
   - Four small convolution blocks, output channels 32/64/96/128 at strides
     2/4/8/16, with GroupNorm and GELU. No claim these filters prove AI use.
   - Fixed filters are the initial reproducible choice. A learned constrained
     filter is an optional later ablation, never silently substituted.

4. Fusion and decoder
   - Project RGB and residual features at matching scales to 64 channels.
   - Concatenate and fuse with 1x1/3x3 convolutions.
   - Decode top-down using bilinear upsampling and feature-pyramid skip
     connections. Include stride-2 residual features for finer detail.
   - Upsample final logits to tile size; output one local-edit logit per pixel.
   - T0 includes no MoE, SAM, diffusion reconstruction or selective zoom pass.

5. Full-image mask
   - Convert tile logits to probabilities and combine overlaps using positive
     spatial blending weights normalized by their accumulated coverage.
   - Remove padding. Save the continuous map at the original image dimensions.
   - Check every valid pixel receives coverage, including corners and edges.

6. Detection score
   - Starting rule: mean of the highest-scoring 1% of valid full-image pixels.
   - This pooling fraction is an initial hyperparameter, not a fact about edit
     size. Compare 0.1%, 0.5%, 1% and 2% on validation only if justified.
   - Keep localization and image-decision thresholds separate.
   - No image metadata, original image or ground-truth mask enters inference.

Testable versions (same capacity and inference, different supervision):
T0: ordinary training using originals and local edits; segmentation loss.
T1: T0 plus matched processed controls and balanced processing across labels.
T2: T1 plus matched-view localization consistency and outside-mask agreement.
T3: T2 plus an auxiliary processing predictor; optional mechanism ablation.

T3 processing predictor:
Pool fused features and predict known recipe categories/parameters using an
MLP. Use only labels supported by recorded recipes. Mask unknown labels.
It is a training-time auxiliary head and is discarded at inference.
Predicting processing does NOT guarantee disentanglement. Retain this head
only if ablation shows a useful effect; otherwise the final model omits it.

==========================================================================
4. PROPOSED FINAL MODEL AND HOW IT IS CHOSEN
==========================================================================
Default final candidate F1:
The SAME ResNet-18 + residual CNN + feature-pyramid architecture, trained on
the full verified training split with the winning controlled objective,
full-image tile inference, frozen validation thresholds and documented limits.
This is a real final-model option, not merely a toy awaiting replacement.

Optional capacity candidate F2:
Replace only the RGB backbone with pretrained ResNet-50. Keep data, decoder
width, crop size, objectives and evaluation identical where possible.
Measure both capacity-matched scientific comparisons and practical runtime.
Adjust batch/accumulation explicitly if memory differs; record that change.

Final selection rule:
- Choose the smallest candidate with repeatable validation improvement on
  tiny edits at the same controlled false-positive operating point.
- Check all-edit localization, unseen-editor validation and processing
  robustness; reject a candidate that wins only through a harmful tradeoff.
- Report GPU memory, time/image and parameter counts.
- Keep ResNet-18 if ResNet-50 does not justify its additional cost.
- Freeze the selection before the independent test is opened.

A global context branch or selective refinement may be investigated only if
measured failures require it. Neither is part of the committed first version.
The final architecture is conditional on experiments; its accuracy is unknown.

==========================================================================
5. DATA: WHAT TO CREATE AND WHY
==========================================================================
For each source photograph, aim to create matched groups:
A. Original photograph -> empty local-edit mask.
B. Original with verified non-content processing -> empty local-edit mask.
C. AI local edit -> verified local-edit mask.
D. The same edit with processing variations -> corresponding edit mask.

Apply sampled processing recipes to BOTH positive and negative classes.
Do not let file type, JPEG quality, image size, watermark or folder provenance
predict the label. Keep encoding/export handling comparable across classes.

Safe initial processing controls:
- Moderate JPEG recompression, for example quality 70/85/95.
- Mild blur, evaluated separately from stronger destructive transformations.
- Resize experiments as a separate condition with geometrically transformed
  masks and explicit checks that the tiny edit survives.

Reconstruction controls:
VAE/editor round trips may be useful but are not automatically clean negatives.
Inspect whether they alter content. A zero local-edit mask here means no
deliberate local semantic edit, NOT that the pixels are camera-original.
Exclude or relabel content-changing controls. Report this category separately.
Do not impose consistency after processing has erased the forensic evidence.

Masks:
- Verify polarity and meaning from dataset documentation and visual checks.
- Prefer original lossless masks, not screenshots or JPEG viewer assets.
- A requested inpainting mask may differ from the actually modified region.
- Keep uncertain boundary/affected regions marked as ignore where warranted.
- Preserve original mask plus documented evaluation mask; never silently edit.
- Image subtraction is a diagnostic, not automatic AI-edit ground truth.

Tiny bins, defined on the full original image before cropping:
>0 to <0.5%; 0.5% to <2%; 2% to <10%; >=10% edited area.
The aggregate tiny category is >0 and <2%. Genuine images form a separate bin.
Always report sample counts; an empty bin is N/A, never zero performance.

Manifest fields:
sample_id, source_id, image_path, mask_path, label, edit_type, editor_name,
editor_version, source_dataset, license, width, height, mask_area_fraction,
split, pair_group_id, processing_recipe, image_sha256, mask_sha256,
mask_verified, provenance_notes, optional ignore_mask_path.

Split rules:
- Split SOURCE identities before augmentation, crop creation or edit creation.
- All derivatives of a source remain in the same split.
- Check exact hashes and near duplicates across splits.
- Keep a separate editor-held-out validation condition for development.
- Reserve different unseen editor/source conditions for the final test.
- Previously inspected development examples remain development examples.
- Previously used test feedback cannot be advertised as untouched test data.

Data scale targets are planning targets, not current inventory:
- Debug: 8-16 verified source groups.
- Controlled pilot: at least several hundred independent source groups when
  available; balanced source-group budgets across T0/T1/T2.
- Paper-scale: expand verified sources and generators within compute limits,
  with enough tiny edits and genuine negatives for meaningful intervals.
Do not inflate dataset size by counting augmented copies as new sources.
With very few genuine images, a claimed 1% false-positive rate is unreliable.

6. TRAINING OBJECTIVES AND INITIAL SETTINGS
==========================================================================
Segmentation objective:
Lseg = foreground-balanced BCE + soft Dice on edited samples.
For genuinely empty masks use BCE; handle empty Dice cases explicitly.
Ignore padded pixels and uncertain mask regions in every pixel loss.
Start with BCE and Dice weights 1.0 each. Record class-balancing/clipping.

Consistency objective for aligned views of the SAME local edit:
Lview = mean absolute probability difference between matched views,
balanced between foreground and background so background cannot dominate.
Use only valid reliable pixels. Geometric transforms require mapping both
predictions to a common coordinate system before comparison.
Start with mild photometric/compression pairs at matching geometry.

Outside-mask agreement:
For original/edit pairs, encourage matching predictions outside a dilated
known edit/ignore region. Also retain supervised negative targets.
Skip pairs without trustworthy correspondence or background preservation.
An all-zero model could satisfy consistency; segmentation supervision remains
essential and must be checked for collapse.

Starting T2 loss:
L = Lseg + 0.1 * Lview + 0.1 * Loutside.
T3 additionally uses 0.05 * Lprocessing.
These weights are initial engineering choices, selected on validation only.
Log every component separately, not just their sum.

Crop sampling:
Half the sampled tiles initially intersect an edit; the other half contain
background/negative controls. Sample by source group so large images and
multiple exports do not dominate. Include hard textured negative regions.
Evaluate entire images with their natural edit prevalence.

Initial optimizer and compute:
- AdamW, pretrained RGB LR 1e-4, new modules LR 3e-4, weight decay 1e-4.
- Mixed precision on compatible CUDA; gradient scaling and finite-loss checks.
- Start microbatch 2, accumulation 4; profile memory before increasing.
- A matched pair uses memory for both views: log images and groups per step.
- Freeze BatchNorm running statistics; do not silently switch normalization.
- Record scheduler, warm-up, total optimizer updates and random seeds.
- Initial comparison budget: 5,000 optimizer steps per variant, with
  validation every 500 steps; revise only from development learning curves.
- Compare with equal source coverage/steps and report extra paired-view cost.
- First seed 42; confirm leading comparisons with seeds 42, 123 and 2026.
- Save best-validation and latest checkpoints, optimizer/scaler state, RNG,
  full config, dependency versions, data hashes and repository revision.

Local GPU previously recorded: RTX 2070 SUPER, 8GB. Recheck availability.
Kaggle GPU type/quota must be inspected; do not assume a particular GPU.
Use the local GPU for debugging and bounded pilots; scale on Kaggle if needed.
No training-time or accuracy guarantee is made before profiling.

8. EXPERIMENT ORDER AND GATES
==========================================================================
P0. Audit and specification
WHAT: Verify source data, labels, split independence and related-work overlap.
HOW: Inspect documentation, representative images/masks, hashes and recipes.
WHY: A model can look successful by learning bad labels or dataset shortcuts.
GATE: Audited manifests, visible examples and documented exclusions exist.

P1. Implement and verify T0
WHAT: Build the compact detector and native-tile evaluation pipeline.
HOW: Check shapes, coordinates, padding, coverage, gradients and checkpoint
reload; overfit 8-16 verified groups to test learning capacity.
WHY: Separate software/data bugs from research failure.
GATE: Finite losses; repeatable saved inference; noncollapsed maps; clear
training-mask learning. This is a debugging result, not generalization.

P2. Controlled pilot
WHAT: Train T0, T1 and T2 with matched budgets and the same initialization.
HOW: Save raw maps, inside/outside mask distributions and validation metrics.
WHY: Test whether controls and consistency help rather than more capacity.
GATE: Improvement on held-out development sources without unacceptable
false-alarm increase. Otherwise inspect masks, processing severity and loss
balance; report a negative finding rather than adding modules blindly.

P3. Confirm mechanism
WHAT: Repeat leading comparisons across seeds; optionally test T3.
HOW: Remove one loss/data component at a time; include an equal-compute or
extra-augmentation control to check whether more training explains the gain.
WHY: Attribute improvement to the proposed method.
GATE: Stable effect and documented uncertainty; eliminate ineffective modules.

P4. Scale and choose the final candidate
WHAT: Train F1 on more verified data; test F2 only if resources justify it.
HOW: Keep data protocol fixed, profile throughput and compare validation.
WHY: Establish useful performance and reasonable cost.
GATE: Frozen model, thresholds and evaluation code before final testing.

P5. Baselines and final independent evaluation
WHAT: Compare against available reproducible prior models on the same data.
HOW: Run matching input/evaluation rules; record baseline score orientation,
checkpoint provenance, native training data and any overlap risk.
WHY: Published numbers from different datasets are not direct comparisons.
GATE: Reproducible prediction files, uncertainty estimates and limitations.

P6. Paper and release package
WHAT: Write methods, protocol, results, ablations, failures and limitations.
HOW: Generate tables from saved metric files and link every figure to run ID.
WHY: Reviewers must be able to verify the actual contribution.
GATE: Claims match measurements; no placeholders presented as results.

9. EVALUATION: WHAT COUNTS AS SUCCESS
==========================================================================
Primary localization endpoint:
Mean per-edited-image IoU on tiny edits (>0 and <2%), with threshold selected
on validation under a predeclared genuine-image false-positive constraint.
Also report pixel F1 and pixel precision-recall AUC, with aggregation defined.
Do not mix global pooled-pixel IoU with mean per-image IoU without labelling.

Detection:
Image AUROC, image AUPRC, sensitivity at validation-selected operating points
(initially 5% false-positive target; 1% only with adequate negative samples),
and the ACTUAL test false-positive rate with uncertainty.
An operating point selected on validation does not guarantee test FPR.

False alarms:
Report image false alarms and predicted-positive pixel fraction separately
for untouched, JPEG, resize, blur and verified reconstruction controls.
Report any component-area rule used to define a localization false alarm.

Breakdowns:
Edit-size bin, editor, edit operation, processing severity, resolution.
Report failures on large/multiple edits as well as tiny edits.
Empty genuine masks do not enter mean edited-image IoU as perfect scores.

Uncertainty and statistical comparisons:
Use paired source-group bootstrap intervals (initially 2,000 resamples).
Keep all variants of a source together; do not treat tiles as independent.
Show seed variation separately. Report counts and effect sizes, not just
one best seed or an unqualified accuracy number.

Engineering:
Peak GPU memory, trainable/total parameters, tile count, time/image at stated
resolutions, preprocessing time and hardware. Synchronize CUDA for timing.

Success criterion:
Consistent tiny-edit improvement versus the SAME model trained normally,
at comparable false-alarm operating points, plus acceptable all-edit results
and unseen-editor transfer. A good in-domain score alone is insufficient.
Failure criterion:
No stable benefit, gains explained by extra compute/data, or increased false
alarms that erase the benefit. In that case revise/reject the hypothesis.

12. RISKS AND RESPONSES
==========================================================================
Too few verified masks -> audit/acquire data before claiming model failure.
All-background predictions -> inspect positive sampling, label polarity,
loss terms, raw distributions and mask survival; do not only lower threshold.
Object-edge false alarms -> textured/object-boundary negatives and qualitative
review; do not assume every strong edge is a manipulation seam.
Editor-specific shortcut -> held-out editors and matched processing controls.
Composite seams from training construction -> use native editor outputs and
boundary controls; report how training examples were constructed.
Severe processing removes evidence -> quantify degradation; do not force
invariance or claim guaranteed recovery of information that was destroyed.
Auxiliary task hurts localization -> remove it based on ablation.
Large model exceeds memory -> sequential tiles, smaller microbatch and
accumulation; profile first and log any change in crop scale or context.
Deadline pressure -> reduce claims/scope honestly; never manufacture results.

- Diagnosis of Entry 9 Failure: The previously reported 75% accuracy in the error audit was driven entirely by class distribution (150/150 edited detected, but 50/50 genuine falsely flagged; balanced accuracy = 50.0%).
- Root Cause 1 (Threshold Conflation): The code applied the pixel segmentation threshold (0.35) as the whole-image decision boundary. Because whole-image top-100 tile activations on pristine scenes naturally exceed 0.35 due to texture and compression, every sample was classified as positive.
- Root Cause 2 (Train/Test Domain Mismatch): Historical classification heads were trained strictly on 384x384 crops (with noisy global labels), but evaluated on 384x384 resized whole images. This caused severe score compression where both genuine and edited images produced scores hovering between 0.70 and 0.78 (genuine mean 0.7253 vs edited mean 0.7389, separation gap = +0.0136).
