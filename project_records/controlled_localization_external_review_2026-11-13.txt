Technical Gaps & Mathematical Vulnerabilities to FixA. Architecture & Feature Alignment (Section 3)Stride Mismatch in Fusion (Section 3.2–3.4): The RGB branch (ResNet-18) outputs features at strides 4, 8, 16, 32, while the Forensic branch outputs features at strides 2, 4, 8, 16. That means only strides 4, 8, 16 have direct dual-branch pairs (1+1 fusion). In models/decoder.py, explicitly specify that stride 32 comes solely from the RGB branch (projected to 64 channels as the top of the feature pyramid), strides 16, 8, and 4 concatenate projected 64-channel RGB and 64-channel forensic maps (128 -> 64 via 1x1 + 3x3 conv), and stride 2 is a forensic-only skip connection fused after upsampling from stride 4.Fixed High-Pass Filter Trainability (Section 3.3): "Fixed high-pass initialization" is slightly ambiguous—if requires_grad=True is left on that first layer in T0, it becomes a learned unconstrained filter immediately. Explicitly lock the 9-channel residual extraction layer (requires_grad=False) across T0–T3 so it remains a true fixed high-pass stem.BatchNorm .eval() Mode Override (Section 3.2 & Section 6): In PyTorch, calling model.train() resets all child BatchNorm2d layers to training=True even if requires_grad=False is set on their affine parameters (weight and bias), which causes running mean/variance to keep updating on microbatches of size 2. You must override train(self, mode=True) inside rgb_encoder.py to force every BatchNorm2d module into .eval() mode during training so running statistics stay truly frozen.Spatial Blending Function & Logit vs. Probability Blending (Section 3.5): Specify the exact blending window: a 2D Hann (raised-cosine) window with a floor of 1e-3 so boundary pixels at image corners still receive non-zero weight when no overlapping neighbor exists. Additionally, test blending logits before sigmoid (or calibrate after blending), because averaging post-sigmoid probabilities across overlapping tiles pulls confident peaks toward 0.5 near tile seams.Top-1% Pooling Scales with Image Megapixels (Section 3.6): Taking the mean of the top 1% of pixels means a 100x100 edit (10,000 pixels) covers 1.9% of a 720p image (filling the entire top-1% pool) but only 0.08% of a 12MP (4000x3000) camera photo—meaning 92% of the top-1% pool on a high-res image is forced to average background pixels, diluting the image detection score on high-resolution photos. Alongside 0.1%, 0.5%, 1%, 2%, include a fixed-area top-$K$ pixel count (e.g., top 2,048 or 4,096 pixels, equivalent to a 45x45 or 64x64 patch at native resolution) on validation.B. Training Objectives & Gradient Pathology (Section 6)L1 Consistency Vanishing Gradient near Zero (Lview & Loutside, Section 6): You define Lview = mean absolute probability difference (|p_1 - p_2|) after sigmoid. Because $\frac{\partial p}{\partial z} = p(1-p)$, if the network pushes background probabilities close to 0 or foreground close to 1, the gradient through sigmoid vanishes, or L1 creates constant-sign oscillations around decision boundaries. Use symmetric KL divergence (with temperature $\tau=1$) or Charbonnier / Smooth-L1 on logits/probabilities with a stop-gradient (detach()) on the cleaner view (View A/C acts as teacher for compressed/blurred View B/D). Asymmetric teacher-student consistency prevents the model from satisfying Lview by degrading the clean prediction down to match the heavily compressed prediction.Paired-View BatchNorm & Memory Accounting (Section 6): With microbatch = 2 source groups and 4 views per group (A: original, B: processed original, C: edited, D: processed edit), a single microbatch forward pass actually contains 8 tiles (2 x 4 x 384 x 384). Even on an 8GB RTX 2070 SUPER in FP16, this is comfortable (~1.8–2.4 GB VRAM for ResNet-18), but if you compare T0 (which only needs single views) against T2 (paired views), ensure T0 processes the exact same number of total tile forward passes per optimizer step so T2 does not secretly see 2x more images per step.Dilated Boundary Ignore Zone for Loutside (Section 6): You rightly note dilating the known edit mask before computing Loutside. Specify the exact dilation radius in pixels (e.g., 15px–21px dilation kernel) because JPEG 8x8 DCT blocks and Gaussian blur bleed across the manipulation boundary into unedited pixels.C. Data Construction & Shortcut Prevention (Section 5)Double-JPEG / Re-encoding Asymmetry (Section 5): A classic forensic bug occurs when Category A (Original) is loaded directly from a camera JPEG, while Category C (AI Edit) is decoded, composited in RGB, and saved to PNG or re-saved to JPEG. Even before applying Recipe B/D, Category C has undergone an extra decode-encode cycle. Enforce a canonical lossless intermediate rule: decode the source image once, save A and C in identical lossless 8-bit PNG before applying matched JPEG/blur/resize recipes (B and D) via the exact same PIL/libjpeg-turbo pipeline and subsampling (4:2:0 vs 4:4:4).Actual-Change Verification on AI Edits (Section 5): Diffusion inpainters frequently hallucinate or alter pixels outside the user mask (via full-image VAE decoding, as highlighted in INP-X and GAP-SAM), OR fail to change pixels inside a tiny mask. Define two explicit pre-manifest checks in audit_data.py:Composite vs. Full-VAE flag: Record in the manifest whether the editor pastes the generated region back onto the original canvas (pixel-composite) or passes the whole image through a VAE (full-vae).Minimum edit signal check: Compute mean absolute RGB difference $\vert{}\text{Edit} - \text{Orig}\vert{}$ inside the mask; if a "tiny edit" has near-zero change inside the mask (editor ignored the prompt), quarantine it to an ignore or unverified list rather than training the detector on invisible edits.D. Evaluation & Metrics Edge Cases (Section 9)Pixel AUPRC Memory Bottleneck (Section 9): Computing exact precision-recall AUC across all pixels of 500+ native-resolution images (500 x 12MP = 6 billion floats) will crash RAM (>24 GB). Specify in metrics.py that corpus-level Pixel AUPRC uses fixed-bin histogram accumulation (e.g., 1,000 threshold bins in [0, 1]) or per-image AUPRC averaged across edited images.Validation Threshold Instability at 1%–5% FPR (Section 9): Order-statistic thresholds (like the 95th percentile of genuine validation scores for 5% FPR) have high variance when $N_{\text{genuine}} < 200$. Require at least 200 independent genuine source images in validation to lock the 5% FPR threshold, and report the exact binomial confidence interval (Clopper-Pearson or Wilson score) alongside the test FPR.3.
